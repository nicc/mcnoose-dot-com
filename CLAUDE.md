# mcnoose-dot-com

Portfolio site: a bathroom wall. Wallpaper header with framed cross-stitch → painted dado rail → white tile grid (one project per tile) → skirting board. Builds to `dist/`: `index.html` (everything else inlined) beside `projects.json` and `logos/`.

## Token efficiency
Use tokens efficiently at all times — in this file, in replies, in tool use. Read only what the task needs; don't restate diffs.

## Aesthetics are the product
The vibe is the key outcome, not a finish. Treat look and feel with the same rigour as function:
- Iterate visually: `npm run shots [-- firefox|webkit] [--fixtures]` → read `shots/<browser>[-fixtures]/*.png` (incl. per-tile close-ups) before and after every visual change.
- `?fixtures` (dev only) swaps in `src/dev/fixtures/` test logos: solid, fine lines, tone, small text, colour, moiré, no-size SVG, PNGs.
- Communicate in felt terms first (what it's like to look at), then mechanism. Show screenshots.
- Name register conflicts early; don't split the difference.
- One coherent scene: every surface (wallpaper, embroidery, frame, tiles, rail, skirting, prints) is lit by the same physical room (`src/room.ts`, `ROOM_*` in cm): a window on the wall behind the viewer (key), a ceiling light (fill) and floor bounce (`ROOM_BOUNCE`, diffuse: lights undersides, casts no shadows). Reflections come from the same window by mirror geometry. Clouds (`src/clouds.ts`, `ROOM_CLOUD_*`): the window light wanders randomly (smoothed random LFO); the scene dims by the window's share of the light via one shade layer, not per-surface re-shading; reflections (glass, tiles) follow the sky via `--glint`; `ROOM_CLOUD_BALANCE` splits room vs reflections. `src/sunlight.ts`: window light colour (`ROOM_LIGHT_KELVIN`, black-body tint at ~60% for eye adaptation, multiply layer over the scene, off at 6500K) and the sun patch (the window's 2×2 panes and bars thrown onto the wall, placed by `ROOM_SUN_ELEVATION_DEG`/`_AZIMUTH_DEG`, color-dodge = exact multiply-up, soft by low-res upscale, `--sunlit` from the cloud loop). Sunset (`src/sunset.ts`, `SUNSET_*`): one pass from the ROOM_* daylight to dusk then held — kelvin, patch elevation/azimuth/strength/softness, room dimming, reflection fade, the sky colour in the glass's reflected panes, each with its own curve; applied by the cloud loop through `setSky` (sunlight.ts keeps the sky so re-renders resume it; the tint compares against the kelvin it last applied) and `skyInGlass` (repaints only the panes); nothing else redrawn.
- **Always light dynamically — a must, for everything.** Every surface computes its shading from `lightsAt(room, its own wall position)`, so it responds to the room controls and varies across the wall. Never bake a fixed light direction, never paint highlights or shadows by hand, never share one lighting across a wide surface (split it into lengths/tiles lit at their own positions).
- Expect many rounds, especially halftone print, wallpaper, skirting, hover effects.

## Constants
- CSS custom properties on an element need `style.setProperty`; `Object.assign(el.style, {'--x': …})` silently does nothing.
- Every tweakable value lives in `src/config.ts` → CSS vars set in `src/scene.ts`. No magic numbers in CSS/TS.
- One `KEY: value,` per line: the dev panel's save rewrites them in place (`tools/config-writer.ts`).
- New keys appear in the panel automatically, in the folder `src/config-groups.ts` assigns; add the key to that section of config.ts (a test enforces section order) and a slider range in `src/dev/panel.ts` `RANGES`.
- Units: sizes in tiles (1 = one tile edge) unless suffixed `_PX` / `_DEG`. Group keys by prefix (`EMBROIDERY_*`, `BULLNOSE_*`).

## Layout rules (tested in `src/layout.test.ts`, `tests/e2e/`)
- Portal, not responsive: the wall is anchored once (centred) and stays put across resizes. Tiles, grout, rail lengths, embroidery and any wall texture never move; resizing reveals/hides wall. Anchor textures to `--wall-x`, never the viewport.
- Desktop (`hover: hover` + `pointer: fine`): also pinned to the physical screen via `screenX/Y` (polled per frame; no move event), smoothed by `PinFilter` (`src/pin.ts`: easing `PIN_SMOOTH_MS`, steady-drag lag cancelled). Tests wait on `html[data-pin=settled]`. Browser zoom: screen positions are scaled to page px by `zoomScale` (pin.ts: innerWidth/outerWidth, snapped to zoom steps, sanity-checked against dpr so docked devtools don't read as zoom; ≈1 in Firefox, whose positions zoom too); any devicePixelRatio change (zoom, another screen) re-centres the wall and restarts the pin. Left-edge drags/window moves reveal wall; top-edge moves scroll to compensate, growing wallpaper upwards (`--wall-y`) past the top.
- Projects crossfade (`REFLOW_FADE_MS`) when they change tiles; fades resume across re-renders via negative `animation-delay`.
- Tests wait on `html[data-rendered-width]` after resizes (resize event lags the viewport change in Chromium).
- Re-anchor only when tile geometry config changes or one full tile + `MIN_PEEK` either side no longer fits (`anchorFits`).
- Tiles square, ≤ `TILE_MAX_PX`; sized at anchor time to fit width and height (svh) with `MIN_PEEK` peeks. Never grow back until re-anchor.
- Projects fill fully visible tiles that show `PROJECT_PEEK` of each neighbour, row by row; other tiles blank; re-flow as soon as a window move or resize changes which tiles qualify; `TRAILING_ROWS` after; page ends at skirting. Wall height (rows) is fixed at anchor time (`wallRows`): narrowing re-flows projects into trailing rows, the skirting stays put.
- Halftone prints are cached per project; resizes move canvases, never re-print.

## Projects
`public/projects.json` (ordered `{title, url, logo}`) + logo files in `public/logos/` (SVG/PNG, any colour; darker + more opaque = more ink). Copied beside `index.html` and fetched at load (`src/projects.ts`), so adding a project on the server needs no rebuild; the wall waits for it (its height depends on the count). Logos must be same-origin (the halftone reads their pixels). Bad entries are skipped with a console warning; `src/projects.test.ts` checks the repo's file and logos. e2e waits on `.skirting` after `goto`.

## Wallpaper (`src/wallpaper/`)
Cooper Hewitt scan 1939-45-7 (CC0, ca. 1875). `npm run prepare:wallpaper` (scripts/prepare-wallpaper.ts, tools/wallpaper-prep.ts) → seamless half-drop `scan.webp` + per-pixel ink map `inks.png` + `palette.json`. `render.ts` (pure): recolour per ink (`WALLPAPER_<INK>` colours, shift-based so print grain survives), procedural pebble emboss + ink relief, lit by `shade()`. Production: baked at build by `tools/wallpaper-bake.ts` (`virtual:wallpaper`, config.ts values, no runtime compute). Dev: rendered live (`index.ts`) for the panel. Background anchored to wall origin. Age (`age.ts`, `PAPER_AGE*`; not `WALLPAPER_` so the live pattern isn't re-rendered): wall-anchored, non-repeating layers over the pattern — a multiplied tint (yellowing, tide-marked stains, the frame's clean patch + grime halo at 0°, angle-blurred by `PAPER_AGE_HALO_SPREAD_DEG`) and seam strips every 53cm, lit per pixel from the room's light (`PAPER_AGE_SEAMS` master, 0 = none; `_SEAM_GAP_MM` wavering joint with lit/shaded edges, `_LIFT`, `_TEAR`, `_SHARPNESS`, `_DIRT` patchy grime band; `_OFFSET_CM` places a reference seam from the embroidery centre (0–53 = one roll); `_SHIFT_MM` pattern mismatch: the wallpaper is then hung as one CSS-background strip per roll, each nudged vertically — no canvas cost); cached, redrawn only when the view leaves the drawn area.

## Embroidery (`src/embroidery/`)
Hand-charted sampler (`chart.ts`: glyphs for the letters used, corner sprig, auto layout) painted on canvas (`draw.ts`: aida, X stitches, mitred wood frame) lit by the room's lights rotated into the frame's tilt; window reflection placed by `reflectedWindow` and slid by `parallaxFactor`. Size = `EMBROIDERY_STITCH_SIZE` × chart. New letters need new glyphs. Site title is a visually hidden h1. `src/frame.ts`: click/tap/Enter turns the frame over (CSS 3D card, `ABOUT_FLIP_MS`); dragging turns it on its nail (in the hanger's notch: `--nail-y`, from `nailDrop` with `ABOUT_HANGER_DROP_CM`/`_TILT_DEG`; grabbed point stays under the pointer; touch: press-and-hold first); let go, it swings back as a physical pendulum (period from its real size; `EMBROIDERY_SWING_DAMPING`, `_STICK_DEG` friction hold) and is re-lit once settled (`frameTilt(c)`: live while moving, else where it settled). The glass reflection is drawn about the nail and counter-rotated live (`turnReflection`), so it holds still on screen. Experiment `EMBROIDERY_FALL` (`src/fall.ts`): not held and past `EMBROIDERY_FALL_DEG`, with `EMBROIDERY_FALL_CATCH` it drops straight down, pivots on the rail at its lowest corner (pitch + roll), and tumbles off screen (without, it tumbles from the nail); `EMBROIDERY_FALL_BLUR` is a vertical SVG blur on the layer, region kept around the frame; in a fixed 3D layer seen from the viewer's eye (room `eyeCm`/`viewCm`); a nail stays. Don't build frame DOM while fallen: its canvases are shared singletons. `back.ts` draws raw oak boards + aged kraft dust-cover (`ABOUT_STAINS`, `ABOUT_EDGE_WEAR`) and a sawtooth hanger at the nail (real size in cm, convex-pressed brass lit by the room, `ABOUT_HANGER_TARNISH`: patina, verdigris in crevices), lit like the front; the note is Nic's real handwriting (`src/about.ts`): ink-only line images cut from a photo by `tools/prepare-note.py` (photo in git-ignored `note-src/`), laid out on a canvas over the paper (`ABOUT_NOTE_ZOOM`, `_SPACING`, `ABOUT_INK`, `_INK_STRENGTH`), multiplied into the paper; an invisible mailto link over the email line; sr-only text. The card is a box `--frame-depth` deep (= `EMBROIDERY_STANDOFF_CM`, which also sets the shadow) with four oak sides (`drawEdges`), turning about its mid-depth so each face rests at z=0. The turned-away face also gets `visibility: hidden` at the turn's halfway point and `pointer-events: none` (headless WebKit ignores backface-visibility; WebKit hit-tests hidden backfaces). Playwright WebKit can't show 3D: check turning visually in Chromium/Firefox.

## Wood (`src/wood/`)
Shared by frame and (later) skirting. `grain.ts`: flat-sawn oak growth rings with cathedral figure, pores, colour drift → albedo/gloss/relief (optionally periodic along the length). `board.ts`: lights a board from a cross-section profile + grain relief; finish sheen is scaled by the gloss map and streaks along the grain. `wear.ts`: rubbing on convex/high profile, grime in hollows and mitre joints, patchy along the length. Lit by a list of room lights.

## Surfaces (`src/surface/`)
Shared by glass now and tile glaze later. `spots.ts`: dried water, `limescale` 0 (droplet rings) → 1 (crust + drips); seeded per surface and clustered like splashes, so never a repeating texture. Size from shared `WATER_SPOT_SIZE` (same physical droplets everywhere). `reflection.ts`: crisp daylit-window reflection placed by the scene light, on its own screen-blended layer, slid with parallax as the view scrolls (`parallaxOffset`; window moves under screen pinning don't count). Dried marks are stains, not wet: never light them.

## Tiles (`src/tiles/`)
`surface.ts`: page px → wall cm (`WallMap`), per-tile glaze tone, cushion-edge CSS shadows per room light. `glaze.ts`: per-tile ageing canvas (crazing + dried marks, worse over the bottom `TILE_GRIME_ROWS`), extended over the joints the tile owns (left, above, and below on the last row) for grout ageing (`grout.ts`: discolouration, grime, mould, limescale, erosion, cracks — soft marks, clipped to joints). `reflect.ts`: each tile traces the room (plain floor, window wall, walls, ceiling — no floor pattern) through its own tilt + waviness; 20×20 canvas, blurred, re-traced on scroll for on-screen tiles only, from the eye (`ROOM_EYE_FOLLOW`, shared with the glass). Per-tile seeds from wall position: nothing repeats. Tiles stand `TILE_THICK_CM` proud of the wallpaper; rays bent back into the wall hit the paper above the seam (sampled from the real pattern, `tiles/paper.ts`). Fresnel is Schlick relative to head-on. 

## Trim (`src/trim/`)
Painted dado rail capping the tiles and the skirting the page ends on; one pipeline for both. `profile.ts`: cross-sections in cm — rail (round top back to the wall, quirk + bead, cove, flat face `RAIL_FLAT_CM`, rounded bottom), skirting (routed from one board: `SKIRTING_DEPTH_CM` thickness at the round, `SKIRTING_RELIEF_CM` how proud the round stands of the face, rounded quirk, flat face; the board's top shows as a foreshortened ledge from eye height, with the dust on it). `length.ts`: `trimLength` builds tile-wide lengths, lit by `lightsAt` + `viewAt` at both ends and blended across (no steps at joins); the profile self-shadows (soft cast shadows + diffuse occlusion relative to each row's own normal, `shadowSoftness` in `wood/board.ts`); grain/paint/wear/scuffs in wall coordinates so lengths join seamlessly; cached per trim + length. `scuffs.ts`: rub line at the floor, shoe scuffs and chips on the face; `SKIRTING_SCUFF_LOW` clusters them at the floor or spreads them up the face. Strokes and dust are sized in cm. Painted finish shared in `wood/paint.ts` (`PAINT_*`); profile softening is in cm and interpolated (tall boards band otherwise). Highlights use the real eye direction (`viewAt`), so flat faces below eye level stay matte. Seam with the paper (contact shadow, joint line), dust (`trim/dust.ts`: soft clumps + fibres, wall-seeded, lit at the ledge; on both trims and the frame's top and inner bottom lip; shared `DUST_SHADE`), the rail's cast shadow onto the top tile row. Joints against the rail and skirting are a fine caulked line (`GROUT_EDGE_CM`).

## Wiping (`src/wipe.ts`)
Mouse only (touch drags scroll). Round soft brush `WIPE_WIDTH_CM`; dust on rail/skirting clears in one pass, tile marks/limescale per `WIPE_LIMESCALE_STUBBORN`. Dabs logged in wall cm and replayed onto freshly drawn canvases (`beginSurfaces`/`wipeable` at render); tile ageing is two canvases (fixed: crazing + grout; marks: wipeable). Frame dust isn't wipeable (frame drags rotate). A drag that wiped swallows the next click.

## Halftone
Dots come from the `halftone-print` package (our own: ~/source/play/halftone-print, github nicc/halftone-print; changes go there, released by tag). `src/halftone/print.ts` composes logo + title per tile and calls `renderHalftone`. Pitch fixed in CSS px. Title stays in DOM as `.sr-only`; shown as plain text if printing fails. `html[data-printed=true]` when all prints settle. Each print also draws a clean canvas (original logo, solid title); hover/focus opens it out from the centre (radial mask on `.tile-clean` and `.tile-ink`, driven by the registered `--reveal` property; `PRINT_HOVER_FADE_MS`, `@media (hover: hover)`), so the re-flow animation on the print itself is untouched. Project links open in new tabs.

## Performance
First load paints wallpaper and tiles first: on-screen rail lengths and the sampler front are `soon` jobs (later.ts) run just after the first paint (rail shows as plain paint, sampler fades in); `data-printed` waits for them. Later redraws are immediate.
The scene renders into `#stage`, 1.5 tiles wider than the window each side (`#app` clips); window moves within that slide the stage (`translate3d`) and only past it rebuild; a move that changes which tiles qualify for projects re-flows in place (`reflowProjects`: prints moved between tiles, tile layers kept) unless the wall would need another row. `renderScene(…, visible)`: projects fill only tiles fully in the window; overscan trim lengths draw later; tile reflections trace only near the window (`slideStage` traces what slides into view). Tests measure tiles within the window, not row ends.
Canvas caches key on wall position: round derived positions (float noise from page↔wall maps re-renders everything on every window move). Re-renders mustn't redo eye-dependent work (tile reflections memoise per eye). The per-pixel loops (wood, paint, wear, scuffs, board shading, tile reflections, paper age, the frame's back) allocate nothing inside and hoist whatever varies only by row or column; keep float expressions in their written order (re-association changes bytes) and run `npm run identity` after touching them. Per-frame loops (clouds) update ~15 Hz and set variables only on the elements that use them, never the root. Kept canvases can be wiped by a GPU reset (Firefox, monitor plugged in): main.ts checks the frame's centre pixel every 2 s and on tab return, and if clear calls `forgetCanvases()` (scene.ts: every module's canvas cache) and re-renders; a pixel-density change re-renders too (`recover.spec.ts`). New canvas caches must be added to `forgetCanvases`. `tests/e2e/memory.spec.ts` (Chromium) repeats drags, resizes, scrolls, flips and idling and fails on steady heap/node/listener growth.
